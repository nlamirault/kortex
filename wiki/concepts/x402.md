# x402 (Internet-Native Payment Protocol)

x402 is an open, neutral standard for internet-native payments that revives the dormant
**HTTP 402 "Payment Required"** status code to let clients and servers transfer value
directly, without traditional payment infrastructure.

## Core Idea

The web was built with a payment status code — HTTP 402 — that was never given a protocol.
x402 fills that gap. It frames the missing native payment layer as the **"Internet's
original sin"**: HTTP could serve content but never charge for it, so the web fell back on
human-centric flows (forms, accounts, KYC, API keys) that autonomous software cannot
navigate.

The protocol turns payment into a normal part of the request/response cycle. A client
requests a resource; if payment is due the server answers `402 Payment Required` with the
terms; the client pays instantly in stablecoins; the server returns the resource. No
account creation, no API-key management, no centralized gatekeeper. Settlement happens
on-chain, so "money moves at the speed of the internet."

x402 is **blockchain-agnostic** — it supports all EVM-compatible chains, Solana, and
others — and charges **zero protocol fees**. Stablecoins (USDC referenced via ecosystem
partners) are the primary payment vehicle, though the standard is extensible to traditional
payment methods. Governance sits with the **x402 Foundation**, which launched operationally
in 2026 with support from Alchemy, AWS, Cloudflare, Stripe, and Vercel.

## The 402 Flow

1. **Request** — an AI agent or user sends an HTTP request for a protected resource.
2. **402 response** — if unpaid, the server replies `402 Payment Required` with accepted
   payment terms.
3. **Payment** — the client pays instantly using stablecoins.
4. **Access** — the server verifies settlement and returns the resource.

Integration is a middleware concern, not a rewrite. From the site:

```js
app.use(paymentMiddleware({
  "GET /weather": {
    accepts: [...],
    description: "Weather data",
  },
}));
```

## Key Properties

- **Internet-native** — payment rides inside the existing HTTP request/response cycle.
- **Chain-agnostic** — EVM chains, Solana, and more; not tied to one ledger.
- **Zero protocol fees** — no rent extracted by the standard itself.
- **Instant settlement** — value moves on-chain in-band with the request.
- **No accounts / no KYC / no API keys** — removes the human-centric onboarding friction.
- **Decentralized** — no centralized gatekeeper mediating access.
- **Extensible** — open to traditional payment rails alongside stablecoins.

## Use Cases

- **AI agent monetization** — agents pay per call without a pre-provisioned account.
- **API pay-per-use** — meter access at the request level, drop API-key management.
- **Agentic commerce** — machine-to-machine value transfer at scale.
- **Paywalled content** — charge per fetch instead of per subscription.

## x402 vs Other Agentic Payment Standards

x402 approaches agent payments from the **transport layer** (HTTP + on-chain stablecoin
settlement), whereas [[concept:agent-payments-protocol-ap2]] works from the **agent layer**
(cryptographic mandates, extending A2A and MCP) and [[concept:universal-commerce-protocol-ucp]]
works from the **commerce-data layer** (product/cart schemas). They are complementary, not
mutually exclusive: an agent could discover a purchase via UCP, authorize it via AP2
mandates, and settle it over x402.
